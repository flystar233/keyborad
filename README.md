# ESP32-C3 智能桌面小键盘 (BLE Keybrick)

基于原理图 **`Schematic1` / `Board1` V1.0（智能桌面小键盘，嘉立创EDA）** 重写的固件。

功能：**BLE HID 键盘** + 6 组键位预设（掉电保存） + **OLED 状态显示** + 电池电量
+ 倒计时定时器 + 节拍器 + 蜂鸣器 + **5 颗 WS2812B 灯效**。

---

## 0. 与原工程的关键差异

原工程（即本目录里 `reference/` 归档的那份代码）是按**另一块板**写的，引脚对不上。
新固件按原理图重新分配，并修掉了几个真问题：

| 项目 | 原工程 | 本固件 | 原因 |
| --- | --- | --- | --- |
| 按键 K1~K5 | GPIO 2/3/4/5/8 | **GPIO 0/2/20/7/8** | 原值把 GPIO4/5 当按键，但这两个脚是 OLED 的 SDA/SCL，**硬冲突** |
| OLED | 软件 bit-bang I2C，SCL=7/SDA=6 | **硬件 I2C，SDA=GPIO4 / SCL=GPIO5** | 排针就在 4/5；硬件 I2C 快得多，且不怕被 BLE 中断切碎 |
| 刷屏方式 | 每字节一次 I2C 事务（上千次） | **512 字节帧缓冲，分 4 次事务推完整屏** | 原来的写法刷一屏要几十毫秒，会被 BLE 打断 |
| 按键消抖 | 主循环里 `delay(5)` 逐键重复读 | **非阻塞轮询 + 独立状态机** | 原来每轮最多阻塞 25ms，还会漏掉快速点按 |
| 定时器/节拍器 | `hw_timer` 中断 + 主循环 `delay` | **纯 `millis()` 状态机，零 delay** | 不占硬件定时器，不和灯效/BLE 抢时间片 |
| 蜂鸣器 | `tone()`（软件） | **LEDC 硬件 PWM** | 出音期间完全不占 CPU，音准不受中断影响 |
| 电池检测 | `A0`(GPIO0)，分压 0.6357，VREF 2.878 | **GPIO3，分压 0.5，`analogReadMilliVolts()` 走 eFuse 校准** | 原值引脚是错的（GPIO0 在本板是 K1）；本板分压就是 100K/100K |
| 状态指示灯 | 单颗 LED (GPIO10) | **5 颗 WS2812 承担状态指示**（GPIO10 在本板是蜂鸣器） | 引脚本来就冲突；灯珠比单色灯信息量大得多 |
| BLE 断线重连 | 只有一句注释 `// How to reconnect automatically?` | **断开 3 秒后自动重新广播** | 原工程断开就再也连不上，必须复位 |

> 原工程的引脚定义（`def.h`）与它自己的原理图**本身就不自洽**（`ADC_PIN=A0` 与 K1 撞脚、
> `BTN_3_PIN=4` 与 OLED SDA 撞脚）。本固件以**原理图**为准。

## 1. 从原理图整理出的接线（代码就按这个写的）

| 网络 | 引脚 | 说明 |
| --- | --- | --- |
| 按键 K1 | **GPIO0** → R3 0Ω → K1 → GND | 按下为低，内部上拉。**strapping 脚** |
| 按键 K2 | **GPIO2** → R4 0Ω → K2 → GND | strapping 脚，板上 R6 10K 上拉 |
| 按键 K3 | **GPIO20** → R5 0Ω → K3 → GND | 同时是 **UART0 RXD** 默认脚 |
| 按键 K4 | **GPIO7** → K4 → GND | |
| 按键 K5 | **GPIO8** → K5 → GND | strapping 脚，板上 R8 10K 上拉 |
| WS2812 数据 | **GPIO1** → R13 100Ω → LED1 `DI` | LED1..LED5 级联（WS2812B-2020-V6），LED5 `DO` 悬空 |
| 灯珠电源开关 | **GPIO21** → U6 `AO3401` 栅极 | P-MOS 高边开关：源极 3V3、漏极灯珠 VDD 轨，**栅极拉低才导通**。同时是 **UART0 TXD** 默认脚 |
| OLED SDA | **GPIO4** | 4 针排针：`GND / 3V3 / SCL / SDA`（原理图上网名标成了 `SCK`，是符号遗留，实际接 SDA） |
| OLED SCL | **GPIO5** | SSD1306 128×32，**I2C 7 位地址 0x3C**（不是 0x78，见第 5 节④） |
| 蜂鸣器 | **GPIO10** → R10 1K → Q1 `S9013` 基极 | NPN 低边，蜂鸣器正极接 3V3，D3 1N4148WS 续流。**高电平响** |
| 电池检测 | **GPIO3** ← R9 100K ← BAT+，R15 100K 下拉 | 分压 **0.5**：4.20V 满电 → 2.10V。C6 100nF 滤波 |
| BOOT 键 | GPIO9 → GND | 板上 R7 4.7K 上拉，只用于进下载模式 |
| 灯效切换开关 U4 | **GPIO6** → SH-1806SA → GND | **循环切换灯效**（见 3.5）。内部上拉，闭合读到低 |
| USB | **GPIO18 = D−、GPIO19 = D+** | 芯片内置 USB-Serial/JTAG；日志也走这里 |
| 充电 | U1 TP4056 + U2 TLV75733PDBVR LDO | R20 2.4K 设充电电流 500mA |

**空闲引脚只剩 GPIO9（BOOT）**，其余全被占用。
GPIO11~17 是模组内部 SPI Flash 引脚，不可引出。

## 2. 编译 & 烧录

```powershell
cd "ESP32-C3 BLE Keybrick"

# 只编译
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run

# 编译 + 烧录（自动找串口；本板必须用这个脚本，原因见第 5 节）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\flash.ps1

# 指定串口 / 跳过编译
powershell -NoProfile -ExecutionPolicy Bypass -File tools\flash.ps1 -Port COM16
powershell -NoProfile -ExecutionPolicy Bypass -File tools\flash.ps1 -Port COM16 -SkipBuild

# 看日志（115200 8N1）
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" device monitor --port COM16 --dtr 0 --rts 0
```

> **不要用 `pio run -t upload`**，本板必失败（`Wrong boot mode detected (0xd)`），原因见第 5 节。

第一次跑脚本如果提示"未对文件进行数字签名"，用上面带 `-ExecutionPolicy Bypass` 的写法即可。

当前构建占用：**RAM 12.2% (39.9KB/320KB)，Flash 78.9% (1033KB/1280KB)**。
Flash 余量已经不多（BLE 协议栈本身很大），后续如果再加功能可能需要调整分区表。

## 3. 操作方式

### 3.1 正常模式（默认）

K1~K5 各自发送**当前预设**里定义的 HID 报文。长按不发送键值（留给模式切换）。

### 3.2 模式切换

| 操作 | 进入 | 再操作 |
| --- | --- | --- |
| **K4 长按**（2s） | 节拍器 | 再长按 / 串口 `n` 回正常 |
| **K5 长按**（2s） | 定时器设置 | 再长按 / 串口 `n` 回正常 |
| **K4+K5 同时长按**（1 秒内先后到） | 键位预设切换 | K3 确认 / 串口 `n` 回正常 |

> 组合键是靠"两个长按事件在 150ms 窗口内到齐"判定的，所以两个键要差不多同时按住。

### 3.3 各模式的功能键

| 模式 | K1 | K2 | K3 | K4 | K5 |
| --- | --- | --- | --- | --- | --- |
| 正常 | 键1 | 键2 | 键3 | 键4 | 键5 |
| 定时器 | 小时 +1 | 分钟 +5 | 启动/停止 | 复位 | — |
| 节拍器 | BPM −5 | BPM +5 | 开/关 | 拍号 4→3→2 | — |
| 预设切换 | 上一组 | 下一组 | **确认并写回 flash** | — | — |

#### 退出模式会怎样（两个都完全结束）

| 模式 | 退出后 |
| --- | --- |
| **节拍器** | **立刻停止**：不再出声、不再计数；再进来需要重新按 K3 开 |
| **定时器** | **完全结束**：停止倒数、清掉到点标志、时长回到默认；再进来是干净状态 |

两者都是"退出即作废"，不会在后台偷偷跑。

> 这里改过两轮，记录一下原因：
> ① 最早 `enterMode()` 只改了模式变量，没停 `gMetro.running`，而 `MetroUpdate()`
>    又只看那个标志、不看当前模式 → **K4 长按退出节拍器后它还在后台"哒哒哒"响**。
> ② 修的时候我顺手让定时器"退出后继续后台倒数"，但那样**到点了你也不知道**
>    （声音被限制在定时器界面内），反而像 bug，而且定时器到点后 `fired` 标志
>    没人清，退出再进来会看到残影。现在统一成**退出即完全结束**。
>
> 现在有两层防护：① 退出模式时显式停止 + `BuzzerStop()`；
> ② `MetroUpdate()` / `TimerUpdate()` 只在各自模式下才被调用，
> 即使以后哪里漏改标志也不会在别的模式里出声或继续计数。

调节类按键**按住会连发**（450ms 后每 140ms 一次），所以 BPM 和预设翻页可以快速连续调。

### 3.4 串口诊断命令（单键，不需要回车）

| 键 | 作用 |
| --- | --- |
| `1`~`6` | 直接切到第 N 组预设（并写回 flash） |
| `n` / `t` / `m` / `c` | 切到 正常 / 定时器 / 节拍器 / 预设配置 模式 |
| `a` / `b` | 节拍器 开/关 / BPM +10 |
| `u` / `q` | 定时器 启动·停止 / 复位（等价于 K3 / K4） |
| `v` | **切换"有没有装电池"**（见第 5 节⑤） |
| `s` | 打印状态（模式、预设、电量、电压、连接、灯珠电源轨读回） |
| `p` | 打印当前预设 5 个键的 HID 报文字节 |
| `d` | **OLED 探活** + 冻结屏幕画两个图标和四角标记（查画面是否位移） |
| `F` | 解除 / 恢复屏幕冻结 |
| `P` | 自动模拟按键弹出 5 次（确认文字左边缘固定） |
| `i` | **扫描整条 I2C 总线**（排查 OLED 不亮时最有用） |
| `w` | 唤醒屏幕（重置息屏计时） |
| `g` | **转储 GPIO 交换矩阵**（查"这个脚到底被谁驱动"的利器） |
| `e` | 切到下一个灯效 |
| `k` | 查看当前灯效 + **GPIO6 开关 U4 的实时状态和翻转次数** |
| `r` | 重跑一次 LED 上电自检（红→绿→蓝→白） |
| `x` | **逐颗逐通道检测**：每颗灯依次只亮 红/绿/蓝/白，用来查某颗灯是否某个颜色通道坏了 |
| `o` / `f` | 灯珠电源轨 开 / 关（用万用表量灯珠 VDD 时用） |
| `?` | 帮助 |

`g` 命令的 `out_sel` 含义：**`128` = 普通 GPIO 输出**、`6` = `U0TXD`、`51` = `RMT_OUT0`。
正常状态下应当看到灯珠数据脚是 `51`（RMT 在驱动）、灯珠电源脚是 `128`。

### 3.5 灯效

灯效分两层：**状态指示始终有效**（不会被灯效模式关掉），灯效模式只决定打底的动画。

**状态指示（任何灯效下都看得见）**

| 指示 | 含义 |
| --- | --- |
| 上电自检 红→绿→蓝→白 | 每颗 250ms，确认能亮 / 颜色对 / 正好 5 颗 |
| **第 1 颗灯橙点双击闪**（闪-灭-闪，周期 2.4s） | 正在广播，等你配对 |
| **第 1 颗灯绿点单次心跳**（每 3s 闪 300ms） | 已连接 |
| 按下的那颗**闪白** | 按键反馈，约 350ms 衰减 |
| 蓝色系覆盖整条 | 定时器设置模式 |
| 紫色系 + 白色跳拍 | 节拍器模式，白点是当前拍 |
| 青色系覆盖整条 | 预设配置模式 |
| **整条暗红闪烁** | 电池低电（优先级最高，只有装了电池才会出现） |

> 连接状态只用**第 1 颗灯**表示，不覆盖灯效本身的颜色。
> （第一版是把整条灯往橙色偏，结果彩虹/波浪/跑马/闪烁四档全被冲成同一种
> "橙色乱闪"，用户实际只能分辨出 3 档 —— 已改掉。）

**灯效模式：用板上 U4 开关（GPIO6 → GND）循环切换，共 6 档**

| # | 名称 | 颜色与动态 |
| --- | --- | --- |
| 1 | `STATUS` | **青绿呼吸**（整条，3 秒一个来回）；默认档 |
| 2 | `SOLID` | **青色稳定常亮**，完全不闪 |
| 3 | `RAINBOW` | **彩虹**在 5 颗灯上流动，约 4 秒转一圈 |
| 4 | `WAVE` | **青蓝色波浪**，相邻灯依次起伏，2.4 秒一个周期 |
| 5 | `CHASE` | **橙色跑马灯**带余晖，每 120ms 挪一格，来回跑 |
| 6 | `TWINKLE` | **暖白色随机闪烁**，每 90ms 换一批 |

六档的颜色和动态都刻意拉开（青绿呼吸 / 青色常亮 / 彩虹 / 蓝波 / 橙跑马 / 暖白闪），
所以"点一下换一档"每次都看得出变化。

**切换方式**：每次 U4 检测到一次有效电平翻转（低→高 或 高→低）就切到下一档。
所以**点动按钮和拨动开关都能用，接反了也照样工作**（两个方向都算一次翻转）。
翻转有 40ms 消抖。

也支持串口切：发 `e` 切下一个，发 `k` 查看当前灯效 + U4 开关状态。
OLED 第 3 行右上角也会显示 `1.STATUS` 这样的小字，不开串口就知道当前档位。

> **实机验证**：GPIO6 上电读数为 `raw=1`（内部上拉生效、开关当前断开），
> 说明 U4 确实是"一端接 GPIO6、另一端接 GND"的接法。
> 串口连发 `e` 6 次已验证 1→2→3→4→5→6→1 循环正确。
> **你拨一下 U4，然后串口发 `k`，`toggles` 计数会 +1**，灯效同时切换。

## 4. 烧完/上电后会看到什么

1. 串口打印启动信息（芯片型号、flash、堆大小、各模块初始化结果、电池首次读数）。
2. **5 颗灯自检：红 → 绿 → 蓝 → 白**，每个 250ms。
3. OLED 亮起，进入下面的**简洁状态界面**。
4. 第 1 颗灯**橙色双击闪** = 正在广播。手机/电脑蓝牙里找 **`ESP32-C3 Keybrick`** 配对。
5. 连上后蜂鸣器"哔"一声，第 1 颗灯转为**绿色心跳**，可以打字了。

### OLED 界面

**正常模式平时只有两个图标，一个文字都没有：**

| 图标 | 位置 | 尺寸 | 含义 |
| --- | --- | --- | --- |
| **电池** | 左上 (1,12) | 8×8 | 分 5 档填充 = 电量；**空心 = 没装电池**（不做任何猜测） |
| **蓝牙** | 右上 (115,12) | 8×8 | 已连接时右侧多一个实心点；配对中只有图标；蓝牙未启动则留空 |

```
电池 5 档：              蓝牙（官方 bluetooth.png）：
0%        100%             ...#....
........  ........         ...##...
#######.  #######.         .##..#..
#.....#.  #######.         ..###...    已连接时右侧加 ■
#.....##  ########         ..###...
#.....##  ########         .##..#..
#.....#.  #######.         ...##...
#######.  #######.         ...#....
........  ........
```

**只有按下 K1~K5 时屏幕才有文字**，画在下半屏**固定位置**（左对齐于 x=26），
1.5 秒后自动消失。

> **这里踩过一个坑**：最早弹出文字是"按每段文字宽度居中"的，结果 `K1: Ctrl+C`
> 和 `K2: Ctrl+V` 长度不同 → 起点 x 也不同，连续按键时文字忽左忽右，
> 看起来就像"整个画面在往左跑"。现在改成**固定左对齐**，并先清掉那条带子
> 再画，位置绝对不动。
>
> 相关诊断命令：串口发 `P` 会自动模拟按 5 个键各弹出一次，
> 用来确认 5 段文字的左边缘是否在同一条竖线上。

**切换灯效（U4）不产生任何屏幕变化** —— 灯本身就是反馈，屏幕不用再重复一遍。

#### 图标就是用 u8g2 的官方素材

图标**不是我画的**，而是从 u8g2 官方字体里取的：

| 图标 | 来源 | 大小 |
| --- | --- | --- |
| 电池外框 | `tools/font/bdf/open_iconic_all_1x.bdf` 的 `battery-empty.png` (ENCODING=90) | 8×8 |
| 电池填充 | 按电量比例算出的 5 档；**100% 档与官方 `battery-full.png` (ENCODING=91) 逐像素一致** | 8×8 |
| 蓝牙 | 同字体的 `bluetooth.png` (ENCODING=94) | 8×8 |

> **怎么确定是这些码点的**：open-iconic 的码点并不直观（不是 `'B'` 就是蓝牙）。
> 但那个 BDF 的 `STARTCHAR` 里保留了**原始文件名**，所以是按
> `bluetooth.png` / `battery-empty.png` 这些名字直接定位的，不是猜的。
>
> 顺带说明为什么没用 u8g2 的 `battery19.bdf`（8×19、7 档）：
> 19 像素在 32 像素高的屏上占 60%，而且列数据会跨页，反而更麻烦。
>
> 也考虑过整体换用 U8g2 库，但要重写整个已验证过的显示层，
> 且 U8g2 字体表极大（`u8g2_fonts.c` 源码 38MB），本工程 Flash 只剩 21%，
> 代价不成比例 —— 所以只取素材，不换库。

#### 图标的校验方式（重要）

位图字节**肉眼几乎不可能查错**，这个项目里因此写错过好几次
（符文多一行空白、填充少 2 像素、凸点偏离中线）。所以有 `tools/verify_icons.py`：

```powershell
python tools\verify_icons.py     # 退出码 0 = 全部一致
```

它会：
1. 把 `display_icons.h` 的位图反解成 ASCII 逐格打印；
2. 检查结构（外框上下横线、左立柱、正极凸点、填充是否从左侧连续）；
3. 检查填充是否随档位单调递增；
4. **直接和 u8g2 官方 BDF 里的对应字形做逐字节比对**
   （0% 对 `battery-empty`、100% 对 `battery-full`、蓝牙对 `bluetooth.png`）。

当前结果：`ALL CHECKS PASSED`，三个字形都与官方**完全一致**。

**其它模式**（进这些模式本来就是为了看数据，所以保留文字）：

| 模式 | 显示内容 |
| --- | --- |
| 定时器 | 第 1 行 `> Timer RUN` + 剩余时间；未运行时显示设定的 `HH:MM`；下面两行操作提示 |
| 节拍器 | `> Metronome [RUN]`、`BPM:100 4/4 beat:n`、拍点指示条、操作提示 |
| 预设切换 | 预设名、上下两组键位说明（每 2 秒滚动） |

**息屏策略**：20 秒无操作变暗，30 秒关屏；**按任意键或拨 U4 唤醒**。
低电时（装了电池才会出现）强制变暗省电。

## 5. 四个"这块板一定会踩"的坑（都已固化在代码/工具里）

### ① `pio run -t upload` 会失败：`Wrong boot mode detected (0xd)`

本板 USB 直连芯片内置的 **USB-Serial/JTAG**。固件正在运行时，esptool 默认的 RTS/DTR 复位
序列进不去 ROM 下载模式。PlatformIO 会追加 `--before default_reset`（位置在 `upload_flags`
之后，会覆盖设置），所以只能绕开它 —— 用 `tools\flash.ps1`，它走 esptool 的
`--before usb_reset` 专用序列 + 手动 `write_flash`。

万一 `usb_reset` 也进不去（极少见）：按住板上 **BOOT(GPIO9) → 点一下 RESET → 松开 BOOT**，
然后 `tools\flash.ps1 -SkipReset`。

### ② GPIO20 / GPIO21 是 UART0 的默认 RX/TX 脚

- **GPIO20 = K3**，**GPIO21 = 灯珠电源开关**。
- 上电时 bootloader 会把这两个脚的输出通路（GPIO 交换矩阵 `FUNC_xx_OUT_SEL_CFG`）接到
  UART0 上，空闲置高。
- 后果：K3 读不到按键；**灯珠电源永远拉不低**（P-MOS 栅极高 = 关断）→ 灯珠 VDD 一直 0V →
  **5 颗灯全灭**。
- 这个状态下只调 `pinMode()` / `gpio_set_direction()` **抢不回来**：pad 仍由 UART 驱动，
  固件写 LOW 也拉不下去（实测寄存器读回电平恒为 1）。
- **两道防线**：
  1. `platformio.ini` 里 `ARDUINO_USB_MODE=1` + `ARDUINO_USB_CDC_ON_BOOT=1` —— 日志走 USB，
     不碰 UART0。**这两行不能删。**
  2. `ws2812.cpp` 的 `railDrive()` 在驱动前先 `gpio_reset_pin()`，把输出信号接回
     `SIG_GPIO_OUT_IDX`。**这一句不能删。**

排查方法：串口发 `g`，看 `pin21 out_sel` 是不是 `128`、`in` 是不是 `0`。

### ③ Arduino core 的 HWCDC 会把日志静默丢掉

`arduino-esp32 2.0.x` 的 `HWCDC::write()` 只有在"主机先主动发过数据"（内部 `connected`
标志被置位）之后才真正往外写，否则一律 `flushTXBuffer()` 丢弃。表现是**板子在跑、串口却
一个字没有**。所以日志不走 `Serial`，而是直接写 USB-Serial-JTAG 硬件 FIFO
（见 `include/usb_log.h`），不做任何连接状态判断，主机不读时最多等 20ms 就放弃，绝不阻塞灯效。

另外：**打开串口会让芯片复位或停在下载模式**，因为 C3 的 USB-Serial-JTAG 会被主机的
DTR/RTS 电平影响。看日志时务必带上 `--dtr 0 --rts 0`。

### ④ OLED 地址必须写 `0x3C`，不能照抄原工程的 `0x78`

这是**实机烧录后才暴露的坑**，第一版固件就是这么挂的：

```
[i2c] scanning SDA=GPIO4 SCL=GPIO5 ...
       found device at 0x3C          <- 面板明明在
[oled] addr=0x78 ... ACK=0           <- 但用 0x78 就是不理你
```

原因：原工程用的是**软件 bit-bang I2C**，`IIC_SendByte(OLED_IIC_ADDR)` 把 `0x78`
当原始字节发到总线上，所以那边写 `0x78`（= `0x3C << 1`，8 位形式）是对的。
而 Arduino 的 `Wire` 库吃的是 **7 位地址**，内部会自己左移一位再补读写位 ——
传 `0x78` 进去，总线上实际发出的是 `0xF0`，面板自然完全不响应。

**排查手法**：串口发 `i` 扫总线。如果扫到 `0x3C` 但 `d` 报 `ACK=0`，就是这个地址问题。
`board_config.h` 里已改成 `#define OLED_I2C_ADDR 0x3C`。

### ⑤ 没装电池时 BAT+ 也是 4.2V，而且软件无法区分

这是**实机测量确认**的现象：板上没接电池，但 BAT+ 有 4.2V。**这不是故障**：

TP4056 没接电池时处于恒压(CV)环路空载状态，BAT 脚会一直顶在 4.2V 调节点。
它判定"充满"靠的是**充电电流跌到设定值的 1/10 以下**（R20 2.4K → 500mA，即 50mA）。
而本板 100K/100K 分压只抽走 `4.2V / 200K = 21µA`，比 50mA 小三个数量级，
所以 TP4056 **永远不会判定充满** —— CHRG 红灯常亮、BAT+ 恒为 4.2V。

后果与对策：

- 如果照常采样，OLED 会显示 `4.23V / 100%`，看起来像"满电"，**其实毫无意义**。
- **光靠 BAT+ 电压无法在软件上区分"没装电池"和"电池已充满"**：两者都是 4.2V，
  纹波都在 ADC 噪声量级。要区分得测充电电流，而硬件上没把电流引出来。
- 所以用**明确开关**而不是让软件瞎猜：

  | 位置 | 用法 |
  | --- | --- |
  | `board_config.h` | `#define BATTERY_PRESENT 1` （当前是 `0`，因为没装电池） |
  | 运行时 | 串口发 `v` 来回切换，不用重新烧录 |

  关闭时：不采 ADC、OLED 右上角显示 **`USB`** 而不是假的百分比、第二行显示 `LINK USB pwr`、
  也不会误报低电。装上电池后打开即可。

> 顺带一提：`4.228V` 略高于 `4.20V` 也属正常，是分压电阻 1% 误差 + ADC 在 2.1V
> 附近约 ±1% 偏差的正常散布。要精修就调 `board_config.h` 里的 `BATTERY_CAL`。

### 对 `lib/hid2ble` 做的一处必要修复

原库在 `begin()` 之前调 `setBatteryLevel()` 会**直接崩溃**：

```
Guru Meditation Error: Core 0 panic'ed (Load access fault)
MEPC : 0x4203af04  BLEHIDDevice::setBatteryLevel(unsigned char)
       (inlined) setup()  src/main.cpp:90
MTVAL: 0x00000028          <- 空指针 + 0x28 偏移
```

因为 `Hid2Ble` 构造函数把 `hid` 置 0，而 `begin()` 只是 `xTaskCreate()` 创建一个
任务去**异步**搭建 BLE 栈，`hid` / `inputKeyboard` 要等那个任务跑完才有效。

修复：加了一个 `ready` 标志（在 `taskServer()` 末尾、`pAdvertising->start()` 之后置位），
`setBatteryLevel()` / `send2Ble()` / `sendMedia2Ble()` / `isConnected()` 全部先查它。
另外加了 `reAdvertise()`：**断线重连绝不能重复调 `begin()`**（那会再建一个任务、
重复执行 `BLEDevice::init()` + `createServer()`，最终内存耗尽），只能重发广播包。

## 7. 出问题时按这个顺序查

| 现象 | 处理 |
| --- | --- |
| 串口一个字都没有 | 确认用 `--dtr 0 --rts 0` 开的串口；用 `tools\flash.ps1` 重烧一次；本固件日志不依赖主机先发数据 |
| 灯全不亮 | 串口发 `g` 看 `pin21 out_sel` 是否 `128`、`in` 是否 `0`；再量灯珠 VDD 是否 3.3V；再量 LED1 `DI` 焊盘（用 `f`/`o` 切换电源轨时是否跟着变） |
| 只有第 1 颗亮 | 断在 LED1 `DO` → LED2 `DI` 之间（虚焊/方向） |
| 压一下某颗灯才亮 | 那颗灯焊盘虚焊，补焊（WS2812B-2020 封装很小，常见整片虚焊） |
| **某一颗灯颜色偏黄/偏色** | **黄色 = 红+绿亮、蓝不亮，说明那颗灯蓝通道有问题。**发 `x` 逐颗逐通道检测：如果点"LEDn B"时它不亮或很暗，就是**那颗灯坏了或某个焊点虚焊**，补焊或换灯；如果三色都正常、只是白色偏色，则是个体差异 |
| 颜色红绿反了 | 改 `ws2812.cpp` 里 `show()` 的 `order[3] = {1,0,2}` 字节序 |
| K3 没反应 | 检查 `platformio.ini` 的 `ARDUINO_USB_CDC_ON_BOOT=1` 是否还在 |
| OLED 不亮 | 串口发 `i` **扫 I2C 总线**：扫到 `0x3C` 说明面板在、是地址问题（见第 5 节④）；扫不到任何设备就量排针 3V3/GND、检查 SDA/SCL 有没有插反或虚焊 |
| 按键乱触发 | strapping 脚（GPIO0/2/8）上电瞬间别按住；BOOT(GPIO9) 也别上电时按住 |
| 电量百分比不对 | 万用表量 BAT+ 实际电压，按 `board_config.h` 里 `BATTERY_CAL` 微调 |
| 烧录失败 | 见第 5 节① |
| Flash 不够 | 见第 2 节末尾，需要自定义分区表 |

## 8. 硬件上值得再改的两点（建议，非必须）

1. **给 AO3401 栅极加一只 100K 上拉到源极**。现在靠 R17 10K 也能关断，但上电瞬间
   在 GPIO21 被配置为 GPIO 之前，栅极电位由 UART0 决定；加上拉能让默认状态更确定。
2. **WS2812B-2020-V6 的供电范围是 3.3~5.3V**，现在 3V3 直供在规格内（满电 4.2V 时经 LDO
   稳压到 3.3V），但 5 颗全白峰值约 175mA，会让画面偏暗。如果要更亮，需要改成 5V 供电，
   同时注意数据高电平门槛会变成 `0.7×VDD = 3.5V`，3.3V 的 GPIO 就驱动不了了，
   得加电平转换。目前 `board_config.h` 里 `LED_BRIGHTNESS` 默认 96，就是为了留余量。

**仍需你自己判断的两项**（我无法远程测量）：

1. **蜂鸣器音调**与**灯珠亮度/颜色顺序**（红绿反了就改 `ws2812.cpp` 的 `order[3]`）。
   这些都是主观项，参数都集中在 `board_config.h` 顶部，改完重新烧即可。
2. **电池**：目前按"没装电池"配置（`BATTERY_PRESENT 0`，OLED 显示 `USB`）。
   等你装上电池后，把它改成 `1` 重新烧录，或者运行时串口发 `v` 切换。
   装上后如果显示的电压和万用表不符，调 `BATTERY_CAL`。

日志实现在主机不读时最多等 20ms 就丢弃，这是**有意的**——宁丢日志也不阻塞灯效。
要抓完整启动日志，请在复位后立刻开始读串口（别等自检跑完）。
